# 公园评论分析一体化 Demo

将包含公园和评论的 Excel/CSV 上传后，按 `DS prompt.md` 的 22 类服务生成 0—5 分方面结果、整体概况和问题归因。

## 目录

```text
frontend/       上传、进度、提及率—满意度散点概况和问题归因页面
backend/        文件解析、异步任务、模型适配和 Excel 导出
tests/          样例数据与数据管道测试
var/jobs/       任务临时文件，默认保留 24 小时
docs/           使用说明、Prompt 和 API 接入指南
releases/       可复用源码版本包
DS prompt.md    22 类服务的原始分析规则
run_demo.py     本地服务入口
```

原来的单文件网页与两份样例 Excel 保留在根目录，作为视觉和数据结构参考，不参与新网页的静态数据渲染。

## 启动

```bash
python3 -m pip install -r requirements.txt
python3 run_demo.py
```

打开 `http://127.0.0.1:8765/`。若端口被占用：

```bash
PARK_PORT=8766 python3 run_demo.py
```

### 初步结果归因模式

- 已完成任务可用 `http://127.0.0.1:8765/?job=任务ID` 直接打开，例如当前批次：`?job=da5d25b5f25b49c78329ab34b919872a`。
- 首页“初步结果归因分析”支持上传包含 22 类方面评分的初步结果。系统先生成提及率—满意度概况，再后台强制使用 Codex 按 DS 服务范围执行负面归因，页面显示四阶段进度并在完成后刷新问题摘要。

## 模型模式

- `Codex 运行器`：后端以非交互方式执行本机 `codex exec`。服务器需要提前安装并登录 Codex。
- `Mock 演示`：仅用于原始评论模式的上传、进度、可视化和下载链路测试；初步结果归因模式强制使用 Codex。

模型输入框默认留空，此时使用 Codex CLI 当前配置的默认模型；只有确认服务器渠道支持时才填写具体模型名。
温度和最大输出 Token 在当前 Codex CLI 模式中作为后续 API 适配预留参数；批大小、最大字符数、并发、重试和超时在当前模式中实际生效。

可通过环境变量覆盖 Codex 命令：

```bash
export CODEX_COMMAND='codex exec --skip-git-repo-check --ephemeral --sandbox read-only --color never'
```

模型接入封装在 `backend/analysis.py` 的适配器中。后续收到正式 API 后，新增适配器并在 `make_adapter` 注册即可，无需改动上传、任务、可视化和导出接口。详见 `docs/API_MIGRATION.md`。

## 输入与输出

必需字段支持 `公园名/公园`、`评论` 等别名；无法识别时网页提供手动列映射。模型只接收公园和评论两列，原文件其他列（包括总体评分）会保留在初步结果中但不参与模型分析。

- `初步分析结果.xlsx`：原始全部列、分析状态、22 个方面评分。
- `筛选明细.xlsx`：仅包含方面评分 1—2 的长表记录。
- `问题归因总结.xlsx`：仅包含负面归因汇总和负面证据明细。

0 分表示未涉及，不计入平均分，也不会进入筛选或归因。任一公园/方面只要有一条 1—2 分评论即生成归因；4—5 分评论不参与归因，也不进行矛盾判断。

页面刷新会通过浏览器本地任务 ID 恢复当前结果；服务重启后，后端从任务目录中的 Excel 结果文件恢复概况和归因数据。
