# 使用注意事项

## 两种上传模式

### 原始评论数据

上传 `.xlsx`、`.xls` 或 `.csv`，至少包含：

- `公园` 或 `公园名`
- `评论`
- `评分`（用于保留和导出；方面评分由模型生成）

系统会执行完整流程：列识别 → 分批方面评分 → 0—5 分结果 → 概况散点图 → 负面归因。

### 初步分析结果

上传已经包含 22 个方面评分的结果表。系统不会重新生成方面评分，只会：

1. 读取已有评分并立即生成概况；
2. 仅筛选方面评分 `1—2` 的评论；
3. 按“公园 × 方面”调用 Codex 归因；
4. 生成问题概要、归因短句、独立证据和范围排除记录。

初步结果模式后端强制使用 `codex`，页面选择 Mock 不会改变这一点。

## 归因规则

- `0`：未涉及，不参与满意度、筛选或归因。
- `1—2`：负面，进入归因候选。
- `3—5`：不参与负面归因。
- 归因单位是一个“公园 × 服务方面”组合，不是单条评论。
- 每个归因单元动态输出最多 10 个语义短句。
- 每个短句只绑定支持它的原始行号；同一评论确实表达多个问题时可以重复支持。
- 不属于当前 DS 服务范围的评论进入“范围排除”，不会强行生成问题。

## 运行参数建议

初次测试建议：

- 批大小：`20—30`
- 最大字符数：`20000—24000`
- 并发数：`2—3`
- 失败重试：`1—2`
- 单次超时：`180` 秒

并发数越高速度越快，但更容易受到本机 Codex 运行器、CPU、限流和上下文资源影响。大归因单元会自动执行分批提炼和跨批合并。

## 结果文件

- `初步分析结果.xlsx`：原始列 + 22 个方面评分。
- `筛选明细.xlsx`：评分为 `1—2` 的评论 × 方面长表。
- `问题归因总结.xlsx`：包含 `归因汇总`、`证据明细`、`范围排除` 三个工作表。

## 运行与恢复

```bash
python3 -m pip install -r requirements.txt
python3 run_demo.py
```

默认地址：`http://127.0.0.1:8765/`

端口被占用时：

```bash
PARK_PORT=8879 python3 run_demo.py
```

服务重启后，任务结果从 `var/jobs/<任务ID>/` 的结果文件恢复。任务目录是临时数据，不应纳入源码版本包或提交到公开仓库。

## 对外开放前检查

- 使用 `PARK_HOST=0.0.0.0` 前配置 HTTPS、访问控制和限流。
- 不要把 Codex 凭证放进前端或上传文件。
- 对外环境应设置上传大小、行数和任务保留时间限制。
- 先用 Mock 测试上传链路；正式归因测试必须使用 Codex。
