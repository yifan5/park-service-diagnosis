# 公园评论负面归因 Prompt

## 用途

用于“公园 × 服务方面”的负面评论归因。模型只处理方面评分为 `1—2` 的评论，不重新进行 22 类方面评分。

## 输入变量

| 变量 | 说明 |
| --- | --- |
| `{park}` | 当前公园名称 |
| `{aspect}` | 当前结果表中的服务方面名称 |
| `{ds_scope}` | `DS prompt.md` 中对应服务方面的完整范围、包含项和排除项 |
| `{mode}` | `batch_extract`：分批提炼；`cross_batch_merge`：跨批合并 |
| `{payload}` | 当前批次评论或候选问题的 JSON |

服务名称映射：

- `共享服务` → `便民生活`
- `运动租赁` → `场地设施租用`
- `共享农田` → `共享田园`

## 内置 Prompt 模板

```text
你是公园评论问题归因模型。

当前公园：{park}
当前方面：{aspect}

你只能分析当前方面对应的服务内容，必须遵守以下 DS prompt 服务范围：
{ds_scope}

当前阶段：{mode}

任务要求：
1. 只分析输入中方面评分为 1—2 的负面评论。
2. 只保留属于当前 DS 服务范围的语义。
3. 将相同或高度相近的问题合并，不要把同一问题拆成多个表述。
4. 输出语义提炼后的短句，不得照搬原始评论，不得只截取原文片段。
5. 每个短句应尽量包含具体对象、问题表现和造成的影响。
6. 一条评论可以支持多个问题，但只有在该评论确实同时表达多个问题时才允许重复使用。
7. 每个问题必须绑定实际支持它的原始行号，不能把所有评论行号全部挂到每个问题下面。
8. 最终输出 1—10 个问题；相近问题优先合并。
9. 不分析评分为 0 或 3—5 的评论，不生成正面证据、矛盾判断或复杂推理。
10. 不属于当前服务范围的评论放入 excluded，并说明排除原因。

请严格输出 JSON，不要输出 Markdown、解释文字或 JSON 以外的内容：
{
  "summary": "一句问题概要；需要概括当前方面的主要问题",
  "causes": [
    {
      "text": "语义提炼后的问题短句，不照搬原评论",
      "source_rows": [12, 35]
    }
  ],
  "excluded": [
    {
      "source_row": 52,
      "reason": "该评论不属于当前 DS 服务范围"
    }
  ]
}

字段约束：
- `summary` 必须是字符串；如果没有范围内有效证据，填写“无当前服务范围内有效证据”。
- `causes` 是数组，最多 10 项；每项必须同时包含非空 `text` 和 `source_rows`。
- `source_rows` 只能使用输入 payload 中出现的原始行号，至少包含 1 个整数。
- `excluded` 是数组；每项必须包含 `source_row` 和具体 `reason`。
- 不得创建没有支持行号的问题短句。

输入 JSON：
{payload}
```

## 分批提炼阶段

`mode = batch_extract`。

`payload` 使用评论证据数组：

```json
{
  "park": "示例公园",
  "aspect": "交通配套",
  "evidence": [
    {
      "source_row": 12,
      "score": 2,
      "comment": "原始评论文本"
    }
  ]
}
```

模型需要从当前批次提炼候选问题，并为每个候选问题绑定该批次中真实支持它的行号。

## 跨批合并阶段

`mode = cross_batch_merge`。

`payload` 同时包含全部负面证据和分批候选问题：

```json
{
  "park": "示例公园",
  "aspect": "交通配套",
  "evidence": [
    {
      "source_row": 12,
      "score": 2,
      "comment": "原始评论文本"
    }
  ],
  "batch_candidates": [
    {
      "text": "停车位不足，找车位耗时较长",
      "source_rows": [12]
    }
  ]
}
```

合并阶段必须重新校验每个问题的证据行号，只保留真实支持该问题的行号；最终问题数量不得超过 10 个。

## 后处理校验

服务端在保存结果前执行以下校验：

1. `causes` 中的行号必须属于当前归因单元的负面评论行号。
2. 没有有效 `source_rows` 的问题会被丢弃。
3. 未被任何问题支持、且模型没有明确排除的评论会记录为范围排除。
4. 模型调用失败不使用原始评论截取作为兜底，归因单元标记为失败并保留重试入口。
5. 归因单元只保存问题概要、问题短句、独立证据行号和范围排除记录。
